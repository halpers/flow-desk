# 前端详细设计

M7.26 [RunHistoryBatch](../../docs/m7-run-history-batch.md)在任务记录为当前管理员提供最多10项多选、服务端预览和统一勾选确认。登记响应丢失保留原正文/请求键，逐项处理显示真实完成数；最近批次和完整批次ID可在刷新后找回。请求可取消，关闭停止页面推进；401/403/404清空批次、父任务与相关缓存。当前状态以重新授权读取为准，旧批次完成回执不覆盖后来单项恢复。

M7.23 `RunHistory` 从任务详情按需直读Go的存储状态、保护原因与最近不可变回执，展示归档/恢复预览并要求显式勾选。变更绑定当前run版本及维护代次；响应不确定保留原路径/正文/幂等键，重新读取后可原请求重试，pending可继续已有操作。请求取消、进入/刷新清空和身份作用域防止显示旧详情；401/403/404关闭维护/父详情并清除相关任务缓存。成功重新读取当前状态，恢复不会提示可重跑旧任务；浏览器不直连Agent，见[任务历史设计](../../docs/m7-run-history.md)。

M7.21任务详情提供按需[生命周期预览](../../docs/m7-run-lifecycle.md)，只读Go的计数和保护原因。独立请求取消及刷新清空，权限拒绝清空父任务及缓存；无清理按钮或浏览器直连Agent。
M7.20增加当前页多选和InvestigationArchiveBatch服务端逐项预览；翻页/刷新清空选择，确认固定正文/键，预览或执行失权清空父子内容，成功重新读取真实当前调查，详见[批量归档](../../docs/m7-investigation-history-batch.md)。

M7.19 InvestigationArchive展示快照与保留条件，显式确认后固定路径/正文/键重试，当前调查成功后重新读取；历史标记归档并保留恢复入口，冲突重读和失权清空沿用既有父子锁定规则。详情见[调查历史分层归档](../../docs/m7-investigation-history-archive.md)。

M7.18 InvestigationRestore 展示目标快照/状态及期望当前修订，显式勾选后以固定路径/正文/键请求Go。确认期间锁定历史及父编辑器；成功依据回执提示并重新读取当前内容，重放旧回执不覆盖较新显示。响应不确定原键重试，冲突重读，拒绝清空父子说明，见[历史恢复](../../docs/m7-investigation-restore.md)。

M7.17 SourceInvestigation 的已保存记录增加“查看编辑历史”，InvestigationHistory使用本地状态和AbortController，每次进入/翻页直读Go，不使用共享说明缓存。纯文本展示快照及基线/缺失范围/新修订提示；加载/错误清空旧数据，关闭销毁，保存后再次进入重新授权。默认20条，按服务端固定上界前后翻页，见[历史设计](../../docs/m7-investigation-history.md)。

M7.16 知识库增加独立“调查工作台”，不依赖租户巡检请求或存储在线。InvestigationWorklist 的查询键包含身份、状态及游标，支持筛选/前后页/回首页刷新，使用取消信号、禁用自动重试，加载/失败不展示旧列表。状态选项来自 allowed_statuses；元数据不含说明。继续跟进单独授权读取说明，复用 SourceInvestigation 确认编辑器，成功后重取列表；分页按不变创建位置而非更新时间，见[工作台设计](../../docs/m7-investigation-worklist.md)。

M7.15 租户巡检每项增加“调查记录”，抽屉同时提供指纹查询入口。SourceInvestigation 每次进入直接向 Go 请求当前记录，不跨身份缓存说明；状态选项来自生成契约和 allowed_statuses。保存确认固定说明/状态/修订和请求键，未确认响应保留原快照重试；冲突后可放弃草稿并重新读取，撤权/重读清空旧说明。普通文本展示不解释 HTML，见[调查设计](../../docs/m7-source-investigations.md)。

M7.14 “归档副本清理”及完整版本历史里的 PDF 项增加“完整副本历史”，逐页覆盖热登记和已归档登记。查询键包含身份/版本/游标，每次进入重取，加载与失败时隐藏旧列表并禁用下一页。确认框固定副本及当前代次，同一选择保留请求键和正文以恢复丢失响应；成功显示原回执并刷新列表。页面不提交存储定位，资格由 Go 判断，详见[副本历史](../../docs/m7-source-history.md)。

M7.13 知识库抽屉为内置 admin 增加“租户对象巡检”。查询键绑定用户/租户/游标，仅调用 Go；默认逐页读取，已知版本可进入原版本巡检，未知项显示对象指纹和待核对分类。空页仍可能有后页，刷新回到第一页，错误隐藏旧结果；不显示桶/key/猜测的未知版本 ID。详见[租户巡检](../../docs/m7-tenant-source-inventory.md)。

M7.12 巡检未登记项增加“核验并登记副本”，资格/原因由 Go 返回。确认框固定对象指纹、原件代次和选择凭证，勾选后才可提交；请求中途失败保留原 Idempotency-Key 和完整参数，重试恢复同一回执。成功后失效当前身份的知识缓存，显示登记 ID 并移除该项登记按钮，旧副本可在独立归档副本入口预览。页面不提交桶/key 或改写服务端资格，说明核验观察与后续清理的区别，见[人工登记](../../docs/m7-source-adoption.md)。

M7.11 PDF 版本增加“对象巡检”抽屉，通过 Go 逐页展示只读存储观察与登记对账，提供前后翻页和刷新到第一页。缓存键包含当前用户/租户/版本/游标；进入时重取，失败隐藏旧结果，加载时禁用翻页。页面明确区分列表大小匹配与内容验证，不提供认领/清理按钮，也不显示桶/key。当前权限和游标有效性由 Go 复核，详见[巡检设计](../../docs/m7-source-inventory.md)。

M7.10 文档管理入口增加“完整版本历史”，通过 Go 有界游标逐页读取详情，提供前后翻页及刷新。每次进入页面重取当前资格，加载时禁用归档与翻页操作；候选归档需要勾选影响确认，绑定历史响应中的文档修订。相同版本/修订在丢失响应后保留同一请求键，成功后刷新热列表及历史。当前引用/ACL/会话保护由服务端执行，历史页不提供恢复已清理原文的入口。详情见[历史归档](../../docs/m7-history-archive.md)。

M7.7 知识库文档提供“版本保留与清理”预览，展示保护原因、原大小、日期和状态；只有候选可打开明确确认的清理弹窗。请求按版本/文档修订复用幂等键，丢失响应后可在原弹窗再次确认。清理中轮询版本，禁止激活、下载和 PDF 预览；墓碑保持可见。实际准入、权限和保护规则由 Go 再次校验，见[清理契约](../../docs/m7-retention.md)。

M6.5 在既有确认卡和回执中展示物流建单、接手与办结；接手/办结卡读取 Go 不可变快照中的原/目标状态、办理人和处理原因/结论。浏览器仍只提交 approval_id、版本和批准/拒绝，不能改写工具参数。回执标题区分四种动作，办结回执可查看工单处理记录，见[场景契约](../../docs/m6-business-scenarios.md)。

技术路线：React + TypeScript + Vite + Ant Design + React Router + TanStack Query。该选择沿用参考项目的通用前端技术，不引入钱包或链上依赖。本文包含完整页面目标；当前已提供身份、工作台、知识管理、审批/输入与工单抽屉，具体实现及浏览器证据见[实施记录](../../docs/progress.md)，下文规划路由不表示均已单独实现。

## 2. 智能办理布局

桌面采用三块区域：左侧会话导航；中间消息与输入；右侧当前订单、有效引用及办理结果。窄屏将右侧内容折叠为抽屉，会话导航可收起。

消息展示：

- 用户消息保留输入时间和可识别内容；助手消息展示文本、引用及实际工单回执。
- 进度只显示“查询订单”“检索规则”“等待确认”等用户可理解的说明。
- 工具结果以结构化摘要卡片展示，敏感信息由后端脱敏；不展示内部服务 URL、令牌或模型私有推理。
- 引用展示文档名、版本、页码/段落，点击通过授权 API 打开安全预览。
- 业务执行成功后显示工单编号和详情入口；即使总结失败，已完成的业务结果仍可见。

页面主要状态：idle、submitting、queued、running、waiting_input、waiting_approval、cancelling 和终态。状态以 Go 快照/事件为准，本地状态只补充网络发送和订阅连接信息。

## 3. 会话与发送交互

1. 用户提交时生成 client_message_id 和 Idempotency-Key，在收到明确结果前保持不变。
2. 列表可以显示“发送中”的本地消息占位，收到服务端 message_id 后合并。
3. 202 返回后读取 run 快照并订阅其事件；输入区提示正在办理。
4. 同会话已有活动 run 时保留草稿，提示先处理当前任务；不偷偷创建第二个 run。
5. 网络超时允许重试同一请求键，并查询已有任务，避免重复消息。

waiting_input 使用服务端 input_id/question/choices 渲染补充卡片，通过 input 接口回复；它不是发送普通消息的新任务。waiting_approval 展示精确操作卡片；用户要修改方案时先拒绝原动作，再以新消息发起。

## 4. 确认卡片

卡片内容由 Go display_snapshot 驱动：动作名称、订单/工单编号、即将写入的标题/内容/分类/优先级、政策依据、失效时间和必要风险说明。payload_digest 可保留在协议层，普通界面无需展示技术摘要。

确认按钮的 loading 和 disabled 防止误点，真正幂等由 Go 实现。提交只含 approval_id、decision、expected_version、reason，不提交修改后的工具参数。

- approved：展示“已确认，正在办理”，继续订阅结果。
- executed：展示服务端业务回执。
- rejected/cancelled：显示终结原因，允许新建消息。
- expired/invalidated/version conflict：刷新快照，提示重新生成方案。

用户刷新页面时从服务端恢复卡片，不能仅凭浏览器本地存储保留一张可点击旧确认。

## 5. SSE、重连与刷新

用 fetch + ReadableStream 解析 SSE，支持 Authorization、AbortController、Last-Event-ID；解析器须正确处理拆包、多行 data、注释心跳和 Unicode 边界。

每个订阅维护 run_id、last_applied_seq、message generation/chunk index 和连接状态。last seq 可以在当前会话内短暂保存，业务正文和凭据不放 localStorage。离开页面关闭订阅，后台 run 继续。

恢复算法：

1. GET run 快照，原子替换当前状态、待确认/待输入、草稿/最终消息，记录 last_event_seq。
2. 从该 seq 之后连接事件流。
3. 重复 seq 丢弃；连续事件按序应用；缺口先补拉再继续。
4. 网络断开指数退避并抖动，上限 15 秒；显示连接状态和手动重连入口。
5. 410 游标过期重取快照；401 走单次 token 刷新后重连；403 停止展示并清理受限缓存。
6. message.reset 清空旧 generation 草稿；completed 使用完整内容覆盖。
7. 终态完成后刷新关联订单/工单查询并关闭连接。

SSE 消息只更新相关 query key，禁止重放旧 tool.completed 时重复弹成功提示或重复发业务请求。

## 6. 前端代码与状态归属

```text
src/
  app/                 # 路由、Provider、布局、鉴权恢复
  features/
    auth/
    conversations/
    runs/
    orders/
    tickets/
    knowledge/
    audit/
  shared/
    api/               # HTTP client、生成类型、错误映射
    events/            # SSE parser、事件 schema、reducer
    auth/              # 内存 token、刷新 singleflight
    ui/                # 通用卡片、空状态、错误提示
    lib/               # 时间/金额/脱敏格式、稳定 ID
```

服务端状态交由 TanStack Query；组件管理筛选、草稿、抽屉等临时状态。run 状态 reducer 由版本化事件契约驱动，避免多个组件各自维护一套任务枚举。

query key 至少包含 tenant/user 作用域；logout 或租户/用户变化清空缓存、停止事件订阅并释放附件 ObjectURL。access token 只在内存；刷新流程 singleflight，防止同页并发轮换 refresh token。

## 7. 工单与知识库交互

工单状态和分配操作提交 expected_version，409 后重载详情并保留未提交表单供用户核对。Agent 创建工单与手工创建区分来源，但详情展示相同业务对象。

知识上传先做前端文件类型/大小提示，服务端执行最终校验。上传成功显示索引任务状态而非立即宣称可检索；用有界轮询获取文档版本状态。失败展示原因与重新上传入口；旧有效版本仍可使用。

文档预览通过带身份请求取 Blob 并控制生命周期，不拼带 token 的下载 URL。Markdown 禁止 raw HTML 和自动远程图片，链接限制安全协议并使用 noreferrer；避免来自文档的脚本或追踪资源。

## 8. 可用性和可访问性

- 所有输入有 label，确认/取消可用键盘完成，抽屉和弹窗正确管理焦点。
- SSE 频繁更新不逐 token 触发读屏通知，只对等待输入、确认和终态作有限 announce。
- 颜色之外增加文字/图标区分状态；耗时较长时显示真实进度和取消入口。
- 空列表、无检索结果、权限不足、离线和执行失败都有可操作提示。
- 时间按用户时区展示，API 时间保持 UTC；金额按字符串/精确格式呈现。

## 9. 契约与测试

M1 从 Go OpenAPI 生成 API 类型；事件使用 shared/contracts JSON Schema 及生成类型。生成输出放 shared/api 的明确 generated 目录，保留来源头，CI 检查重新生成无差异。

单元测试覆盖 SSE 拆包/乱序/重复/重置、状态 reducer、401 singleflight、确认过期和取消竞争。组件测试覆盖卡片不同状态、表单校验和安全 Markdown。Playwright 覆盖登录→发起任务→确认→看到工单，以及刷新/断线后恢复。

实现后建立 pnpm dev/build/typecheck/lint/test/test:e2e 等脚本，固定 Node/pnpm 版本并提交锁文件。设计阶段仅检查文档，不宣称前端构建成功。

## M7.3 已实现的 OCR 操作

管理员上传 PDF 时选择文本层、自动无文字页或整页识别；TXT/Markdown 沿用文本上传。版本列表显示方式和 OCR 页数，分页预览标明 text/ocr/empty。含 OCR 内容的版本显示核对确认框，勾选后发送 confirm_ocr=true；Go 最终校验，不依赖按钮禁用保证审核。引用弹窗只根据 Go 返回的 extraction_method 显示 OCR 提醒，不接受模型来源标记。错误使用固定中文指引，不显示原生路径或诊断正文，见[OCR 说明](../../docs/m7-ocr.md)。
## M7.5 PDF 阅读方式和核对

新文档及追加版本可选择原始顺序、双栏先左后右、表格行列对齐，M7.24允许同时选择自动无文字页/整页OCR。列表显示版本固有选择；预览使用等宽、不折行且可横向滚动的文本。非 plain 激活需要核对确认框并发送 confirm_layout，由 Go 最终验证。前端不自动猜测版面，不宣称还原合并单元格；见[M7.5](../../docs/m7-pdf-layout.md)。

M7.24实际同时包含OCR和版面时展示“核对OCR文本和阅读顺序”组合确认，提示对照原件检查字词、数字及行列，勾选后一次发送confirm_ocr和confirm_layout。既有单项审核继续保留；服务端最终强制两项确认，不依赖按钮状态。预览按物理页显示来源，引用只使用Go返回的OCR标记并继续撤回提示，不把mock首句摘要当成完整提取正文。范围和误识别限制见[联合处理](../../docs/m7-ocr-layout.md)。
## M7.9 保留策略编辑

M7.9 在知识库管理区显示“保留策略”，从 Go 读取当前值及策略修订。编辑必须核对适用范围，保存丢失响应时原表单同键重试，改参数生成新请求键。成功后重新 GET 当前值，不以旧写入回执覆盖后来的策略。文档清理请求携带预览的 policy_revision，409 后需关闭确认、刷新预览并重新核对。详见[保留策略](../../docs/m7-retention-policy.md)。

## M7.8 归档副本操作

M7.8 为 PDF 增加“归档副本清理”抽屉，展示登记副本大小、批次及保护原因；恢复至数据库后刷新预览。确认弹窗必须勾选原件/备份核对，提交 expected_source_epoch 与 Idempotency-Key，失败保留原请求键以恢复丢失响应。清理中轮询状态，界面说明零字节标记与数据库原件保留，不展示存储定位；服务端决定最终授权与清理资格。见[完整契约](../../docs/m7-source-cleanup.md)。

## M7.6 账号与角色操作

“账号与角色”按 account:manage / role:manage 显示账号及角色页签；用户和角色类型来自生成的 Go OpenAPI。账号支持分页、新增、改名、启停、多角色及重置密码，内置角色只读；自定义角色从服务端权限目录选择。角色选项支持按名称查找和完整可访问选项，管理表单清楚提示会话失效和自身保护。

丢失响应保留原表单和请求键，未改内容重试同键；成功或关闭表单清空密码及待重试内容。密码不进入存储、通知或 query cache。版本冲突需刷新后重新核对；管理权限与对象范围仍由 Go 决定，knowledge:manage 仅显示管理入口，不能越过基础角色 ACL 或团队范围。见[M7.6](../../docs/m7-accounts.md)。

M7.27扩展[RunHistoryBatch](../../docs/m7-run-history-batch-restore.md)提供独立恢复入口。服务端预览的恢复资格与归档资格分别展示；固定方向/路径/正文/请求键，最近批次标识原目标，刷新后仅推进原批次未完成项。恢复完成后从单项历史核对当前存储，不展示可重新执行旧任务；拒绝继续清空父子内容。

M7.28[SelfPassword](../../docs/m7-self-password.md)为全部当前用户提供本人改密，明确确认全设备退出。密码表单不持久化；改密不自动刷新或重试。请求前建立不含凭据的重新认证标记，成功或不确定时清密码/token/查询缓存并卸载工作台；刷新页面也需显式登录，已知未提交错误可清除标记后重新填写。

M7.30[定时归档](../../docs/m7-run-history-schedule.md)在任务记录中提供独立策略窗口，仅当前admin/run:observe展示。每次进入/刷新直读Go，显示运行总开关、当前修订、持续授权、下一检查和原操作；确认固定正文/键，结果不确定冻结表单并允许原键重试，成功重新授权读取当前值。关闭取消读取，401/403/404清空窗口和父列表缓存。浏览器不调用Agent。

M7.31[超时调查自动回待办](../../docs/m7-investigation-automation.md)位于知识库→调查工作台→调查自动流转。独立抽屉每次重读授权策略，确认后保存固定正文/键，不确定时仅重试原保存或刷新；保存成功重读当前值，401/403/404清除抽屉与工作台缓存。显示总开关、持续授权、DB检查时间和当前可见的最近流转指纹/修订，不展示私有定位。
