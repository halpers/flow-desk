# M7.23 任务历史归档与恢复

本阶段为满足条件的只读任务提供显式归档、恢复及持久操作核对。M7.21 的生命周期候选仍是观察结果；观察本身不会迁移数据，也不代表维护授权。

## 范围与权限

当前版本仅处理最后更新已满 30 天的终态任务（成功、失败、取消或超时）。归档要求业务和 Agent 两侧均没有活动租约、排队/运行/等待命令、未确认回调、未结算模型或向量预算；任务没有业务动作、审批记录、待补充信息、不可变业务回执、引用证据、资源关联或重试链；同一会话没有活动任务。单任务最多 50,000 个业务事件、100,000 行检查点记录。超限或无法确认的条件继续保留。

归档和恢复要求当前租户的 `admin` 角色与 `run:observe` 权限，并重新检查任务、团队、用户和会话身份。查看状态使用现有任务可见性规则。普通操作员可以继续查看自己有权访问的已归档消息、详情与事件，不能授权维护。模型、知识文本或生命周期预览不能授予维护权限。

业务回执、证据、工具结果、命令、回调、预算账本和审计记录继续保留。带业务动作、回执、证据及资源等关联的任务受到保护；已结算的执行账本继续留在原表。M7.26增加[人工确认的任务历史批次](m7-run-history-batch.md)；[M7.27](m7-run-history-batch-restore.md)增加人工确认的批量恢复；[M7.30](m7-run-history-schedule.md)另行提供默认关闭的定时归档；物理删除整个任务和永久清理仍未提供。

## 数据移动与读取

Go 保留 `runs`、`messages`、`run_events` 的身份、外键、消息位置、事件序号、原始时间和载荷哈希。消息正文、引用及动作回执字段移动至 `message_payload_archives`，事件载荷移动至 `run_event_payload_archives`。热表相应载荷清空，`messages_history_read`、`run_events_history_read` 视图按身份合并热/冷载荷，现有授权消息读取、来源事件查找和 SSE 重放继续返回原内容。逻辑行数不会减少。

Python 仅移动自己拥有的 `checkpoints`、`checkpoint_blobs`、`checkpoint_writes` 至对应 `_history` 表。JSONB 与 BYTEA 在数据库内部原样移动，不解码检查点，不把图状态或模型推理返回维护 API。生命周期计数包含热表与冷表。

恢复将相同内容放回热表。第一次维护建立的执行封存永久保留，因此恢复不会重新执行任务，也不会开放旧命令、内部能力、回调、检查点写入或任务重试。需要新的业务处理时，应新建任务并重新取得当前业务授权。

## 持久协议

1. 浏览器读取 `GET /api/v1/runs/{run_id}/history` 并展示保护条件。用户预览归档或恢复，勾选确认。
2. `POST .../history/archive` 或 `POST .../history/restore` 使用 `Idempotency-Key` 请求头和 `expected_version`、`expected_generation`、`confirm` 正文。Go 在授权事务中重新验证条件，写入唯一的 `run_history_operations` 待确认记录与申请审计，并保存原幂等映射。
3. Go 事务外调用 Python `POST /internal/v1/runs/{run_id}/history`。命令包含 Go 生成的操作 ID、可信租户、严格递增的维护代次和目标层；该接口只接受内部服务身份。
4. Python 使用与图执行器一致的逐任务 advisory lock（种子 3），锁定命令并重新盘点；原子建立或推进永久封存、移动全部三类检查点、保存不可变回执。相同操作返回原回执，不重复移动。执行器、命令接收、回调和检查点数据库写入均遵守封存。
5. Go 收到严格匹配的回执后，再次检查当前身份、任务/团队可见性和 Go 保护条件，原子移动消息/事件载荷、保存完成审计、将原操作标记完成。已完成操作不可修改或删除。

跨服务没有分布式事务。调用超时、进程退出、完成审计失败或调用期间权限变化，都保留可追踪的待确认操作。状态接口在 Agent 不可用时仍返回当前授权用户可见的原操作；`POST .../history/operations/{operation_id}/resume` 核对相同操作及代次，再原子完成 Go 一侧。任何当前有权的租户管理员都可核对，原申请人仍记录在操作与申请审计中。Agent 调用成功后的权限拒绝不会向失去权限的调用者返回部分结果。

并发请求受逐任务锁、唯一待确认操作和递增代次约束。通用幂等有效期内，恢复后的旧归档键返回旧不可变回执，不改变较新的存储状态。前端保留未确认请求的原键，也提供继续已有操作；访问被拒绝时清除历史窗口、任务详情和相关缓存。

## 运维恢复

在任务记录中切换到“租户任务”，定位任务，打开“历史归档与恢复”。若状态为“维护待确认”，核对操作 ID 后选择“继续已有维护操作”。该入口使用原操作，不能改写目标、代次或申请身份。Agent 不可用时修复服务连接后继续；若提示保留保护，先处理相应活动执行/未结算记录，不能通过删除保护记录绕过约束。

数据库备份须同时包含 Go 与 Agent 的热表、冷表、维护操作、永久封存和回执；仅恢复载荷而丢失封存会破坏重放约束。普通服务账户不需要 DDL 权限。此阶段没有服务器部署操作。

## 验证入口

Go 的 `TestRunHistory*` 使用每测试独立数据库，验证载荷实际转冷、公开读取一致、恢复及原键回放、内部能力/重试封存、响应丢失、晚期审计失败回滚，以及外部调用期间会话撤销后由另一位当前管理员核对。客户端测试拒绝错误租户、缺字段、未知字段、空值、负计数和尾随数据回执。

Python 的 `tests/test_run_history.py` 使用临时隔离 schema，验证三类检查点字节、热/冷逻辑计数、执行器锁、租户/代次、持久回执回放、写入封存和晚期失败原子回滚。测试数据库由 `TEST_DATABASE_URL` / `AGENT_TEST_DATABASE_URL` 指向专用开发管理员提供，不应使用业务数据库。

合成 HTTP 验收与浏览器 fixture：

```powershell
python scripts/check-run-history.py --env-file work/retention-ci.env --output work/run-history-ci.json --browser-fixture work/run-history-ci-fixture.json
$env:FLOWDESK_RUN_HISTORY_FIXTURE = "../work/run-history-ci-fixture.json"
pnpm.cmd --dir flow-desk-web test:e2e tests/e2e/run-history.spec.ts
```

该脚本要求位于 `work/` 的显式 mock 栈配置，只将自身新建的合成失败任务调整为超过保留期，然后通过公开 API 归档与恢复。浏览器测试覆盖确认、失去响应后的原键重试、已有操作核对界面与权限拒绝清理；其中待确认元数据展示使用故障注入，真实持久待确认状态由 Go 数据库测试验证。脚本或测试存在不等于已经执行；执行结果以本次交付记录为准。
