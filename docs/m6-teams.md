# M6.4 团队与资源权限

本阶段在租户边界内增加团队成员和资源范围。本文先定义交付契约，完成记录以 [progress.md](progress.md) 为准。

- 管理员创建团队、维护本租户启用账号的成员资格，团队最多 50 个；团队名称最长 80 字。成员变更带 expected_revision 和幂等键，同一版本的并发更新只有一个成功。变更写入审计。
- 普通成员仅能列出自己的团队；只有管理员能查看租户账号目录与团队成员列表。账号目录只返回 ID、显示名、角色和启用状态。
- 工单、知识库各有可选 team_id，空值表示租户范围。管理员可设置资源范围。工单仍要求对应角色权限；知识库要求角色 ACL 和成员资格同时满足。管理员保留维护访问权。既有资源默认租户范围。
- 设置工单范围递增 version，并清空已不属于目标团队的负责人；知识库范围变更递增 acl_revision。所有赋权对象必须来自当前租户，普通成员不能自行更改范围。
- Go 在读取、备注、指派、状态变更、Agent 搜索、动作准备和执行时检查当前权限。撤销成员后，旧 action 或客户端幂等响应不能绕过权限。审批只表达对既定动作的同意，不授予成员资格。
- Go 登记任务使用的工单资源。历史助手消息、审批快照、回执和 SSE 回放在资源失权后隐藏内容；用户自己输入的文本保留。知识引用沿用当前版本/角色/团队复核。原始审计、回执与历史记录保持不可变。
- 升级迁移为旧回执和备注动作补齐精确资源引用。旧搜索事件未保存返回的工单 ID，保守关联升级时该租户全部现有工单；因此旧搜索答复可能比实际需要隐藏更多。新增搜索按实际返回 ID 记录。迁移保留原业务事实，不删除历史。
- 成员变更取得租户级排他事务授权锁；资源检查尝试取得共享锁并持有至事务结束，保证已提交撤权后的新操作不能继续写入。授权变更占锁时返回可重试的 AUTHORIZATION_BUSY（409），不持资源行锁等待授权锁。成员变更不锁业务资源。资源移动与引用使用既有资源行锁串行化。
- Python 不读取业务表；只使用 Go 下发的有效版本范围、验证后的证据和过滤后的工具结果。已有聊天仍属于原所有者，没有新增多人会话功能。

浏览器契约由 `api/teams.api` 定义：GET/POST /teams，GET /team-users，GET /teams/:team_id/members，PUT /teams/:team_id/members/:user_id，PATCH /tickets/:ticket_id/team，PATCH /knowledge-bases/:knowledge_base_id/team。team_id 不接受模型或浏览器提供的 tenant_id/actor_id 作为授权来源。

验收覆盖租户外成员/团队拒绝、角色与团队交集、并发成员更新、事务回滚、幂等重放、撤权后的搜索/审批/执行/历史/SSE/引用，以及管理员浏览器维护流程。暂不增加组织树、自定义角色、自动跨租户分享或外部身份目录。
