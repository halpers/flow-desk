# 测试、评测与交付计划

本文给出完整验收目标。M1 已实现工程、身份、迁移与契约，实际验收证据见 [实施记录](progress.md)。框架/API/认证检查不代表模型质量、性能或后续业务功能测试。

## 1. 岗位能力与项目证据

| 能力方向 | FlowDesk 实践 | 应保留的可审查证据 |
| --- | --- | --- |
| 后端工程 | go-zero 分层、API-first、SQL 模型、事务、授权 | 接口契约、生成脚本、事务回滚/并发测试 |
| Agent 编排 | 意图、工具、补充信息、状态、中断和恢复 | 图定义、正常轨迹和失败恢复轨迹 |
| RAG | 版本化索引、权限过滤、混合召回、引用 | 固定问答集、检索基线与改进报告 |
| 工具集成 | 读工具、动作准备、批准执行、后续 MCP 适配 | schema、跨服务协议测试、幂等回执 |
| 质量评测 | 固定任务、基线、失败分类、版本对比 | 可重跑数据集、结果 JSON/Markdown |
| 稳定性与可观测 | outbox、租约、trace、SSE 回放、预算 | 故障注入报告、时延/错误/成本指标 |

此表是项目选型映射，不代表所有招聘岗位都有相同要求。应用工程和平台岗位优先展示以上实践；训练/算法岗位另按目标 JD 补充数据构建、SFT/RL 等实验。

## 2. 测试分层

| 层级 | 用途 | 数据/依赖 |
| --- | --- | --- |
| 单元 | 规则、状态、节点、schema、事件 reducer | 假模型、假工具、固定时钟 |
| 数据库集成 | 约束、锁、隔离、回滚、幂等 | 真实 PostgreSQL、隔离 schema |
| 契约 | `.api`/OpenAPI/事件/工具三端一致 | schema 正反样例、生成产物 diff |
| 服务集成 | Go↔Python 调度、回调、恢复 | 可丢弃环境、确定性假模型 |
| E2E | 登录、办理、确认、工单、刷新恢复 | Playwright + 合成租户 |
| 离线质量评测 | 模型决策、检索、答案与任务完成 | 锁定模型/profile、固定任务集 |
| 故障/负载 | 重试、失联、慢连接、锁与队列 | 故障注入、独立压测环境 |

确定性功能测试不依赖真实模型。真实模型评测独立运行、设置费用预算，不能把模型偶然输出导致的波动混入普通 CI。

## 3. 初始合成数据集

准备两个隔离租户，每租户至少 3 个角色工作人员、50 个订单、10 份政策文档及若干历史工单。所有身份、联系方式、地址和订单均合成。确保有订单同名、政策相似、物流延迟和旧版本文档，用于验证边界。

初始评测集 100 个任务，按下列主标签划分；可另外加次级标签：

| 主标签 | 数量 | 期望 |
| --- | --- | --- |
| 订单/物流事实查询 | 20 | 正确对象、正确状态、时间来源明确 |
| 有依据的政策问答 | 20 | 正确政策和引用，没有无依据条款 |
| 信息补全/多轮 | 15 | 需要时追问，恢复后使用正确对象 |
| 工单/备注办理 | 20 | 必须确认，精确参数，真实回执 |
| 权限和恶意内容 | 15 | 租户/对象隔离，文档指令不能越权 |
| 工具故障与恢复 | 10 | 有界重试、不重复写、说明部分完成 |
| 合计 | 100 | — |

其中 60 条为开发集、20 条为回归验证集、20 条留作最终留出集，并在类别中尽量分层抽样。留出集不用于调 Prompt。固定场景种子、资源版本与模拟时钟，使业务断言可复现。

## 4. 数据集记录格式

每条 JSONL 记录包含 task_id、split、tags、fixture_id、actor_ref、user_turns、expected_tools、expected_business_state、required_citations、forbidden_effects、fault_plan 和 scorer_version。角色和租户使用 fixture 引用，避免把运行密钥写入数据。

评价优先使用可执行断言：是否访问正确订单、是否发生未批准写、工单数量是否正好增加一次、引用版本是否正确。自然语言质量可辅助使用评审模型，但需保存评审版本并对抽样任务人工核查，不能单靠模型自评宣布正确。

## 5. 质量指标与初始门槛

以下为 M5 初始验收目标，达到前必须给出真实测量报告：

| 指标 | 定义 | 初始目标 |
| --- | --- | --- |
| 端到端完成率 | 全部业务/权限/依据断言通过的任务占比 | ≥85%，同时逐类别报告 |
| 工具选择与参数正确率 | 应调用工具及关键参数满足断言 | ≥95% |
| 政策引用正确率 | 引用能支持相关结论且版本有效 | ≥95% |
| 检索 Recall@5 | 标注相关片段进入前五的比例 | ≥90% |
| 未授权业务写 | 越权、取消后或未经确认的新写动作 | 0（硬门槛） |
| 重复业务效果 | 同一 action 重放产生第二次变更 | 0（硬门槛） |
| 敏感信息泄露 | 测试定义的秘密出现在页面/日志/外部请求 | 0（硬门槛） |
| 恢复正确性 | 指定故障后达到预期最终状态 | 确定性故障集全部通过 |

样本量有限，报告同时给出分子/分母、失败案例和多次运行范围，不将百分比包装为生产保证。硬门槛失败必须修复，不能被平均完成率抵消。

## 6. 性能与成本

在固定资源环境记录 CPU、内存、数据库/模型版本、数据规模与并发数；区分普通 API、队列、模型和工具耗时。

- 合成 10,000 订单/10,000 工单，20 并发下普通业务 API P95 初始目标小于 300ms，不含外部模型。
- 本地 Go/Python 同网段、10 活跃任务下，任务接受到首次进度 P95 小于 2s。
- 进程重启后在 60s 内发现未完成任务并进入恢复/明确失败状态；不代表 60s 内完成业务。
- SSE 断线恢复后最终消息、确认状态和工单回执一致，无丢失和重复展示副作用。
- 真实模型端到端延迟单独统计 P50/P95，不以本地假模型结果替代。
- 每任务记录 input/output tokens、模型/重排/embedding 用量与估算费用；缺价格标为 unknown。比较改进时使用同一价格基线和样本。

成本目标在模型选定后制定，以质量门槛下的每任务费用比较。缓存和模型路由优化必须同时报告命中率、权限隔离与答案变化。

## 7. 必测故障矩阵

| 故障 | 预期 |
| --- | --- |
| 创建任务提交后浏览器断线 | 同键重发获取原 run |
| Go 投递成功但未收到 202 | 重投同 dispatch_id，Python 只登记一次 |
| Python prepare action 后崩溃 | 恢复复用 action_id，没有第二份动作 |
| checkpoint 成功、等待回调丢失 | callback outbox 最终补发并显示确认 |
| 工单提交成功、工具响应丢失 | 查回执/重放返回原工单，不新增 |
| 业务成功、模型总结失败 | 展示真实回执和总结失败，不能否认已办理 |
| 用户确认与取消同时发生 | 按锁顺序得到单一合法结果 |
| 执行前订单或政策版本改变 | 旧批准失效，重新生成并确认 |
| 旧 worker 在新代次后回调 | 新事件/动作被拒，图检查点保持单写者 |
| 执行锁连接断开 | 老执行器停止，安全隔离后恢复 |
| 文档索引回调乱序 | 旧版本不能覆盖新激活版本 |
| 文档/角色权限撤销 | 检索与引用复核及时拒绝 |
| SSE 重复、拆包、游标过期 | 去重、正确解析、快照恢复 |
| 模型限流或工具持续失败 | 有界重试，错误与已有副作用明确 |

## 8. 阶段计划

阶段按验收推进，不承诺未结合人员投入测算的日期。

| 阶段 | 交付内容 | 退出条件 |
| --- | --- | --- |
| M1 工程与契约 | 三个可启动服务、固定运行时/锁文件、健康检查、登录种子、迁移/模型生成器、机器契约、Compose | 本地一套命令启动；认证和契约生成检查通过 |
| M2 只读任务 | 消息/run/outbox、假模型图、订单物流工具、进度 SSE、权限与队列 | 从浏览器发起查询，断线重连可恢复，越权用例通过 |
| M3 RAG 和真实模型 | 上传索引、版本激活、混合检索、引用、模型适配及预算 | 固定问答集可重跑，引用和撤回测试通过 |
| M4 业务办理与恢复 | 动作准备/确认/执行、幂等回执、取消、检查点、故障注入 | 重复效果和未授权写为零，故障矩阵通过 |
| M5 评测与展示 | 100 任务、基线/改进对比、trace、性能报告、演示与运维文档 | 报告可复现，质量门槛通过，演示覆盖失败恢复 |
| M6 可选专项 | MCP 标准适配、团队权限扩展或更多场景 | 每项新增能力有契约与效果证据 |
| M7 持续增强 | M7.1 文本 PDF、M7.2 任务运营台、M7.3 扫描 PDF OCR、M7.4 原文件存储、M7.5 规则版面、M7.6 账号与角色、M7.7 版本清理、M7.8 归档副本清理、M7.9 保留策略、M7.10 完整历史与版本元数据归档、M7.11 对象巡检、M7.12 旧副本人工登记、M7.13 租户对象巡检、M7.14 副本历史与退休登记归档、M7.15 巡检调查记录、M7.16 巡检调查工作台、M7.17 调查完整编辑历史、M7.18 调查历史内容恢复、M7.19 调查历史分层归档、M7.20 调查历史批量归档、M7.21 任务生命周期盘点 | 已清理版本详情独立归档、身份隔离与完整历史分页；已知版本范围的未登记对象对账及人工确认后完整性核验登记；已支持当前租户前缀的未知版本发现与受控归属核对、完整副本历史及退休登记移表、人工调查跟进与修订保护、按状态查询的当前租户工作台及升级基线/后续不可变编辑历史；已支持旧快照确认恢复为新修订，以及保留完整内容的旧快照分层归档及同调查多选预览/原子批量归档；已支持当前授权下任务/消息/checkpoint数量与恢复保护的只读盘点；历史物理清理、自动合并/流转、跨租户/租户身份未知目录巡检、自动认领/修复、对象名删除、其他历史数据归档及任意复杂版面待后续 |

M1 的“可启动”只表示工程和健康检查，M4 才具备完整办理功能。不要把生成空 handler 等同业务完成。

## 9. 最终作品交付清单

- 源码、依赖锁文件、生成器及 schema/迁移历史。
- 一条完整演示：查询→检索→确认→执行→工单回执。
- 一条失败演示：写入后响应丢失→恢复→原回执、防止重复建单。
- 固定评测集、版本化报告、具体失败分类和至少一次改进前后对比。
- API/架构/数据/部署文档、合成种子与清理流程。
- README 明确实现范围、模型成本和可复现步骤；简历只填写真实测量结果。

各阶段验收须记录实际命令和结果；M1 已有认证与事务集成检查，后续业务测试与质量评测按表中退出条件推进。
