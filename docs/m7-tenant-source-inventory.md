# M7.13 租户范围对象巡检与归属核对

人工说明与跟进已由[M7.15调查记录](m7-source-investigations.md)提供；本节描述实时列表观察和归属线索，调查记录本身不执行登记或删除。

目标是在仍有可信租户前缀、但版本身份未知时发现历史对象。只列举当前配置桶的 `knowledge/<当前租户>/`；不跨租户或列举任意目录。对象名是外部输入，不是归属或完整性证明。

## 行为与边界

- 仅当前内置 admin 且有 knowledge:manage 的用户可读。委派知识管理权限不获得该入口。
- 独立开关 FILE_STORE_TENANT_INVENTORY_ENABLED 默认关闭，并要求 FILE_STORE_INVENTORY_ENABLED。Go 为唯一入口，Agent 无新数据写入。
- 默认 20、最多 50 个存储条目/页，单次 S3 ListObjectsV2，复用已有大小、时限、编码和排序校验。加密游标绑定用户/租户/存储，15 分钟有效；分页不构成快照。
- 规范旧式和代次键先按可信租户查版本；标准键但版本记录不存在时为 unknown_version，不能关联版本的非标准键为 unrecognized_key。未知对象不返回从名称猜出的版本 ID、hash 或原始定位。
- 已知版本重新检查当前知识库 ACL/团队，无权限项省略；即使该版本目录下的对象后缀不规范，也先检查版本权限，不能借非标准分类绕过。items 可以少于 scanned_count，甚至为空且 has_more=true；翻页使用扫描位置。已知身份返回 document_id/version_id 供人工进入既有版本巡检，hash/格式不一致显示 version_mismatch。
- 存储 I/O 位于事务外；前后复核用户/会话/管理员角色，后置资源授权、登记查询及只读审计同事务；失败不返回部分结果。
- 不验证 PDF 内容、清理标记或未列出对象是否丢失，不证明未知对象可删除。不扫描租户前缀之外、供应商历史版本，不自动登记/修复/删除。

## 验收与复跑

Go 全量测试与 vet 通过；当前测试数量见[实施记录](progress.md)。覆盖已知/未知/非标准/hash 不匹配分类、跨租户范围、委派账号拒绝、期间撤权/角色变化、开关/存储变化、审计失败不返回部分结果、加密游标篡改/过期/跨用户/跨接口，以及隐藏页继续翻页。受限旧 ACL 只在合成记录上构造，现有产品 API 仍保留管理员 ACL 保护。

独立 mock/S3 [公开 API 4/4 报告](../reports/m7/tenant-source-inventory-acceptance.json)验证 25 个当前租户对象分两页、22 个未知版本副本、一个非标准对象、一个已知身份但摘要不匹配对象及一个当前原件。另一个外租户对象不进入结果；查阅前后登记账本及原件 SHA256 保持。逐页 limit=1 隐藏已知版本仍完成扫描，只有 27 个成功页面写审计。

Chrome 新增 2 项验收通过，验证分页/返回/刷新、已知版本进入原巡检、全程 GET 和普通账号无入口。Agent 隔离 schema 49/49、Web 单测 4/4、类型/生产构建通过；原版本巡检 4/4 和人工登记 3/3 已回归。更完整的浏览器结果见实施记录。

执行前先在独立 mock 栈配置 --enable-tenant-inventory；Linux 复跑命令见[存储手册](../deploy/source-storage.md#租户范围对象巡检)，它会创建新合成租户和对象，不可在业务库运行。服务器升级、人工核对、错误处理和回退见[手册 §23](../deploy/server.md#23-租户对象巡检与归属核对)。本地验收不代表生产容量、未知租户目录、全库内容一致性或任意供应商兼容性结论。
