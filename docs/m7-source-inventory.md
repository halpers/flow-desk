# M7.11 S3 对象巡检与登记对账

为有权限的 PDF 版本提供只读、逐页的对象巡检，覆盖迁移前已恢复到数据库、仍保留版本身份但没有 source_objects 登记的旧副本。巡检使用当前配置私有桶和可信租户/版本前缀，不接受任意桶、路径或模型提供的定位。无自动认领、修复、写入对象或删除操作。

## 契约与范围

- `GET /api/v1/documents/:document_id/versions/:version_id/source-inventory?limit=20&cursor=...`，每页默认 20、最多 50 条。返回版本/代次、观察时间、对象指纹、登记 ID/状态、大小/修改时间、可识别的旧式/代次键及对账结果。
- FILE_STORE_INVENTORY_ENABLED 默认 false，显式启用后应用账号额外需要限定 knowledge/ 前缀的 s3:ListBucket。缺少权限或存储返回越界/无序/不合法数据时失败，不将失败当作空桶。
- ListObjectsV2 按当前租户与版本的固定前缀、StartAfter 和有界 MaxKeys 查询。只支持按键排序的普通桶兼容接口；每次仅一页，不扫描全桶。依据：[S3 ListObjectsV2](https://docs.aws.amazon.com/AmazonS3/latest/API/API_ListObjectsV2.html)。
- 游标使用 AES-GCM 加密认证，绑定用户、租户、文档、版本、存储配置与原件 hash，保存代次、定位和 15 分钟有效期。响应和游标不明文暴露桶/key/凭据。变更代次或过期后刷新第一页。
- 存储 I/O 在事务外。读取前后检查当前会话、knowledge:manage、角色 ACL 和团队范围，末次事务复核代次/配置、查询当前登记并记录一次页面巡检审计；撤权或观察期间恢复原件时丢弃结果。
- 响应上限 256KiB，最多观察 51 个对象，继承 5 秒超时、不跟随重定向和不重试。URL 编码只解码一次，遇到原始加号会拒绝整页：SeaweedFS 4.52 将空格列为加号，无法可靠区分对象身份；应用标准键无此字符，供应商兼容测试须包含特殊字符。

## 结果解释

逐个对象展示未登记、登记匹配、当前原件、清理中、已登记清理且当前零字节、大小异常或非标准定位。对象指纹用于与受控运维清单比对，不包含原始路径；旧键仅在版本 hash 匹配且无代次段时标为 legacy，代次键必须满足规范十进制及 int64 范围。

这是对象列表元数据与登记账本的实时观察，不下载或验证 PDF hash，不验证零字节对象的防重写标记元数据。未登记不等于可以删除；列表未出现不等于已登记原件丢失。分页不是一致快照，期间新增或消失的对象需要重新刷新核对。无法关联已知版本的对象、供应商历史版本、任意目录、自动认领和全库完整性修复不在本阶段范围。

## 验收与复跑

协议测试验证 SigV4、固定前缀、URL 编码、分页和大小/顺序/范围限制；隔离数据库测试覆盖当前授权与撤权、跨租户/团队、代次变化、加密游标和审计失败。实际 SeaweedFS 协议探针验证旧式对象、零字节观察、特殊字符逐次解码，以及拒绝有歧义的空格编码。

公开接口 [4/4 报告](../reports/m7/source-inventory-acceptance.json)在独立 mock/S3 栈创建 22 个真实历史对象，以删除该新版本唯一初始登记的方式模拟未登记的旧代次；验证两页无重复、当前原件与未登记分类、无自动认领、游标保护及普通操作员拒绝。恢复后原件 SHA256 一致。脚本不会清空业务 schema，但会主动构造合成状态，只能在临时环境运行，不能在生产执行。

Web 单测 4/4、类型检查和生产构建通过。Chrome 回归 12 项通过，其中新增巡检用例验证 23 个对象的前后翻页、刷新、无写请求和无认领/删除入口；4 项既有用例因未准备历史清理夹具跳过。Agent 隔离 schema 测试 49/49。Go 全量和文档检查证据见[实施记录](progress.md)。

启用权限、开关、沙箱命令及运维复跑见[存储部署](../deploy/source-storage.md#版本范围的只读对象巡检)和[服务器手册 §21](../deploy/server.md#21-s3-对象巡检与登记对账)。不将本地 SeaweedFS 验收当作远程供应商、生产容量或全库完整性结论。
