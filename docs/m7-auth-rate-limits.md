# M7.29 共享持久认证限流

本阶段将登录和本人改密的实例内存额度迁移到Go拥有的PostgreSQL记录。所有API实例连接同一业务库时共享额度，进程重启不会重置；不增加Redis、模型依赖、公网端口或Agent迁移。实施和实际验收以[实施记录](progress.md)为准。

## 额度与公开行为

登录沿用全局每秒2次、突发10次；不按客户端IP、请求account或模型输出创建限流键，不保存密码、账号输入、IP、Authorization或Cookie。改密沿用独立全局每秒2次、突发10次，以及可信tenant/user每分钟1次、突发5次的额度，换实例、IP、会话或重新登录不能补充额度。

登录保持429 RATE_LIMITED，改密保持429 PASSWORD_CHANGE_RATE_LIMITED；拒绝响应增加至少1秒的整数Retry-After，认证响应禁止缓存。额度数据库不可用、操作超时或事务失败返回503 AUTH_RATE_LIMIT_UNAVAILABLE，不退回本地放行，不执行后续bcrypt或修改凭据。限流消耗先独立提交，随后凭据校验或业务失败不会退还次数；限流本身提交结果不确定时也按503拒绝业务。

## 并发与状态管理

auth_rate_limits以固定全局键或可信租户/用户键保存理论到达时间。采用整数时间间隔的GCRA，当前时间来自取得行锁后的PostgreSQL clock_timestamp，应用主机时间不参与补充额度。先锁全局桶，再锁账号桶；同时符合两个额度才原子推进两桶，不在行锁内执行bcrypt或身份业务事务。所有操作受2秒上下文期限限制。

改密账号桶最多4096个。准入前每次最多回收100个已完全补满且15分钟未成功消耗的账号桶；仍有债务的桶不回收。满额时拒绝新桶，不驱逐正在使用的桶。全局桶只有两条。租户/用户关联及键格式由数据库约束校验，跨租户关联拒绝；不提供公开查询或删除限流记录的接口。

## 升级和运维

先备份并执行Go迁移2026111001，使用配套API；Web和Agent公开协议保持，无新增环境变量。共享效果要求所有流量已经离开旧版API，混用仍使用内存额度的旧实例会绕过共享门槛。升级期间先摘流旧实例，再放行新实例；当前单机部署脚本不因此获得无停机或高可用能力。

429按Retry-After等待，不清表、不改available_at、不通过重启补额度。503检查数据库连通性、迁移、锁等待和容量；恢复数据库后额度继续有效。数据库或整库备份回退会连同限流状态一起回退，应在维护窗口处理，不能承诺跨旧备份保留全部最新债务。当前没有按登录账号或IP的附加限流、自适应风控或共享限流管理界面。

本地专项计划验证：独立连接并发争抢同一额度、重建ServiceContext继续拒绝、按数据库时间补充、双桶更新后置失败回滚、租户/账号隔离、满额及安全回收、锁超时/数据库失败拒绝业务，以及真实HTTP的429/Retry-After和凭据不变。具体实测数量在验收后记录。
